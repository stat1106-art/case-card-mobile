# 正式上架流程（給同仁用的案例）

發包人把 GPT 02 的回覆整段（可以一次好幾案）轉給維護人員，維護人員：

1. 每段回覆存成一個文字檔，執行
   `python tools/ingest_gpt_replies.py 回覆1.txt 回覆2.txt …`
   （先加 `--dry-run` 試跑，只看報告不寫檔）
2. 工具會：
   - 抽出所有 format 為 `case-card-app-case` 的小卡資料（前後說明、圍欄、「情境圖：」那一行都略過）。
   - 自然人姓名遮成「姓＋○○」（複姓留兩字），同一批任何一案的全名在其他案也一併換掉。
   - 用電腦版的內容檢查（必要欄位、金額加總、來源卡、過失相抵）＋判決來源欄位檢查完整性，不完整的不上。
   - `hero_type`：GPT 有填且在 14 類就用；沒填就依關鍵字建議一類（標題、標籤加重），**維護人員要逐案確認**。
   - 同一案（同 jid）已上架就略過。
   - 寫進 `cases/`、更新 `cases/index.json`，印出上架報告。
3. 案例分析 .md（2026-10-25 發包人規定，每次上架都適用）：
   - 所有自然人姓名都遮成「王○○」這種寫法——原告、被告、證人、家屬、主管、醫師都算；公司與機關名稱不用遮。
   - 把 .md 和回覆一起交給 `ingest_gpt_replies.py`（檔名要和案例檔同名），或單獨跑 `python tools/mask_analysis_md.py 檔案.md`；工具找「稱謂＋人名」與同批小卡的當事人全名，遮好並列出每一處。
   - **逐檔人工檢查**：沒有稱謂在前的人名（例如「王小明表示…」）工具抓不到，要人工看過每一行。
   - 打包時 build.py 會用同一套規則再檢查一次，還有沒遮的就停止。
   - 回報時寫明：「.md 已遮蔽自然人姓名，共 N 處」。
4. 人工檢查：當事人以外的人名（證人、主管、醫師等）工具抓不到，逐案看事實與見解；確認示意圖類型。
5. 重新打包（`app_mobile/src/build/build.py`；姓名沒遮好會停止）、跑 `tests_cloud` 測試、部署 gh-pages。
6. 回報發包人：新增哪幾案、.md 已遮蔽自然人姓名共幾處、各配哪張示意圖、哪些沒上（「本案不適合現有版型」或資料不完整）與原因、新的打包編號。
