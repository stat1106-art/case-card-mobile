## 一、給 Grok：任務

做一個**本機、單人、一頁式**的小程式：讀 `cases/*.json` 的案例 → 使用者選案例、版型、風格 → 呼叫本包的出圖程式產生 PNG → 顯示並可下載。

技術不限，建議：Python 3.10+ 標準庫 `http.server` 加一頁 HTML（本包已依賴 Python、Playwright、Pillow，不要再加 Node、資料庫或其他框架）。只開在 `127.0.0.1`。

## 二、套件內容（照用，不要改）

| 路徑 | 是什麼 | 規則 |
|---|---|---|
| `casecard/` | 出圖程式（排版、隨包字型、18–19 項檢查） | **不准修改任何檔案**。要改版面請回報發包人，不要自己改 |
| `casecard/skins/` | 9 種風格 | 照用；`classic` 版型才能換風格，其他版型只能用 `original` |

| `reference/cardrender_from_workbench.py` | 工作台裡同一段程式（參考用） | 只讀，不要匯入 |
| `cases/shilin_110_laosu_72.json` | 範例案例（士林地院 110 年度勞訴字第 72 號） | 案例檔格式以這份為準 |
| `docs/card_template.json`、`docs/card_example_shilin.json` | card 的空白結構和完整範例 | 參考 |
| `docs/card_negative_overflow.json` | 字太多的反例 | 驗收用 |
| `requirements.txt`、`setup_first_time.cmd` | 第一次安裝（Playwright、Pillow、Chromium） | 照用 |

### 案例檔格式（`cases/*.json`）
```json
{
  "format": "case-card-app-case",
  "schema_version": 1,
  "title": "給清單顯示的標題",
  "source": {"court": "臺灣士林地方法院", "case_number": "110 年度勞訴字第 72 號",
             "decision_date": "2026-06-12", "jid": "", "url": "https://judgment.judicial.gov.tw/..."},
  "card": { …出圖程式的 card_content，格式見 docs/card_example_shilin.json… }
}
```
法院、案號、日期**只從 source 帶入**圖卡（`build_card()` 已經這樣做），不要另外讀 card 裡的值。

### 版型與風格
- 版型 id：`classic`（新第一版）、`light`（淺色資訊圖）、`standard`（原版）。
- 風格清單：`casecard/engine/skins.py` 的 `list_skins()`，回傳 `[{id, name}]`，畫面顯示 `name`。
- 選了 `light` 或 `standard` 時，風格選單要變灰並固定 `original`，旁邊寫一句「只有新第一版可以換風格」。

## 三、驗收（每條都要過，交件時附上實際畫面或輸出）

1. `python verify_engine.py` 顯示「全部通過」（11 張）。
2. 雙擊 `start_windows.cmd` 就打開瀏覽器畫面；黑色視窗關掉就結束。不需要打指令。
3. 選士林案、`classic`、任一風格，按「產生小卡」：右邊出現圖，下面顯示「檢查全部通過（○ 項）」。
4. 按「下載」存下的 PNG 和畫面上的是**同一個檔案**（同一份位元組，不要重畫一次）。
5. 有一個「草稿標記」勾選框，預設**打勾**（圖右上角出現「草稿」）；取消勾選才出沒有標記的圖。畫面上寫一句：「案例內容由 AI 整理，正式使用前請自己對照判決核對。」
6. 把 `docs/card_negative_overflow.json` 的內容做成一個案例放進 `cases`，按產生：要顯示**沒過的項目和白話說明**（用 `verify_engine.py` 的 `FRIENDLY` 對照表），圖照樣顯示讓人看哪裡爆掉；**不可以自動縮字、刪字或截斷**。
7. `cases` 裡放一個壞掉的 JSON：清單上要標示「這個檔讀不出來」，其他案例照常可以用，程式不當掉。
8. `cases` 新增或修改檔案後，按「重新讀取」就看得到，不用重開程式。
9. 全程不連網（安裝那一次除外）、不上傳任何資料、只開在 127.0.0.1。
10. 畫面文字用台灣常用的繁體中文，不要用中國大陸用語或工程術語（例如寫「產生小卡」不寫「渲染」，寫「檢查沒過」不寫「校驗失敗」）。
